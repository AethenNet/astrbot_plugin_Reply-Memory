>## 可选配置
- **默认开启** 需要真实 @ 与引用：开启「群聊回复增强 → React Pattern」和「智能回复」
- **默认关闭** 需要记忆能力：先配置 Embedding 提供商，关闭    其他记忆类插件

## 简介

ActiveReply 是面向 AstrBot 的群聊增强插件，把主动回复、群聊上下文、长期记忆 RAG、用户屏蔽和可视化控制台组合在一起。

当前版本：**v1.1.0-beta.2**。本版重点：

- 记忆采用「事件 + 原子记忆」两层结构；
- 重要性统一为 0–10，并按类型设置有效期与半衰期；
- 每日自动备份、`STORE_VERSION` 版本闸门；
- 记忆列表批量选择、批量归档/删除、删除可撤销；
- 控制台卡片、详情、原始消息、骨架屏和设置页布局重做。

## 功能

| 功能 | 说明 |
|---|---|
| 消息主动回复 | 概率触发或模型判定；累计 N 条消息后兜底；支持黑白名单 |
| 群聊上下文增强 | 记录昵称、QQ、时间、消息号；支持图片转述 |
| 智能回复 | 解析 `<mention/>`、`<quote/>`，转换为真实 @ 与引用 |
| 自动记忆 | 关键词快速通道 + 后台模型抽取，独立记忆时间线 |
| 两层记忆 | 先写 episode，再拆原子记忆；详情页可展开查看 |
| 记忆 RAG | 语义 + 关键词召回、去重、生命周期、归档、回收站 |
| 记忆管理 | 批量选择、归档/取消归档、删除、Snackbar 撤销 |
| 用户屏蔽 | 全局 + 群级屏蔽；原因、时长、提示、管理员豁免 |
| 联网搜索 | `grok_web_search` 工具，按需检索实时信息 |
| 图片理解 | `enhance_use_image` 查看历史图片并回填描述 |
| 回复调试 | `/replytest` 开启后附带 token、缓存命中率与日志 |
| 控制台 | 状态、群配置、记忆 RAG、屏蔽、全局设置 |
| 数据安全 | 每日备份；数据库版本过高时只读，避免降级写坏 |

## 环境要求

- AstrBot **>= 4.29.0**
- Python **>= 3.10**
- OneBot v11 适配器（`aiocqhttp`）
- 记忆 RAG 需要可用的 **Embedding 提供商**

> 核心聊天/记忆逻辑在更早的 AstrBot 上也能运行，但控制台依赖 4.29.0 的插件页面发现与路由，因此统一要求 4.29.0+。

## 安装与升级

1. 将 `astrbot_plugin_active_reply/` 放入 AstrBot 的 `data/plugins/`；
2. 重启 AstrBot 或在插件页重载；
3. 在配置中按需开启记忆 RAG、主动回复、联网搜索。

升级前请保留：

`AstrBot/data/plugin_data/astrbot_plugin_active_reply/`

第一次使用本版前建议先备份整个目录。插件启动时会：

- 自动创建/迁移 SQLite 表；
- 每次插件启动时，若当天快照不存在则生成一份记忆库快照（在版本检查/迁移前执行）；
- 检查 `STORE_VERSION`；数据库版本高于插件时只读，不再写入。

## 指令

| 指令 | 权限 | 说明 |
|---|---|---|
| `/执行回复` | 管理员 | 立即执行一次主动回复/模型判定，并发送执行日志 |
| `/replytest true\|false` | 管理员 | 开关本群回复调试；别名 `/回复调试 开\|关` |
| `/ban <时间> <用户ID> <原因>` | 管理员 | 本群屏蔽用户 |
| `/ban-all <时间> <用户ID> <原因>` | 管理员 | 全局屏蔽（含私聊） |
| `/remove <用户ID>` / `/pass <用户ID>` | 管理员 | 解除本群屏蔽 |
| `/remove-all <用户ID>` / `/pass-all <用户ID>` | 管理员 | 解除全部屏蔽 |
| `/总结记忆` | 管理员 | 立即总结当前会话；`/总结记忆 quiet` 只回一行结果 |

时间格式：`0` 永久；支持 `1d2h30m`；纯数字按分钟。

## 控制台

### 状态

显示主动回复、上下文、RAG 开关，记忆总数、来源、Embedding 状态，以及本轮召回耗时/降级原因/待抽取条数。

### 记忆 RAG

- 统计、筛选、分页、搜索；
- 卡片显示 `ID / 类型 / 时间 / 群名+群号`，卡片间距 2px；
- 右侧箭头展开详情；详情含基本信息、关键事实、正文、遗忘时间线和原始 JSON；
- 原始消息按摘要卡 + 聊天气泡展示，不含头像，可查看 UID/消息 ID；
- 原始记录为可复制的语法高亮 JSON；
- 加载时显示骨架屏，数据到达后原位替换。

### 归档与批量操作

- 筛选栏右侧的**收纳盒圆形按钮**：只看已归档；
- 左侧**勾选圆形按钮**：进入/退出批量选择；
- 选择模式下勾选多张卡片，可批量：
  - 「归档」/「取消归档」；
  - 「删除」——进入回收站；底部 Snackbar 的「撤销」会恢复整批删除；
- 批量操作逐条执行并汇总成功/失败。

### 群配置

- 抽屉中的「群配置」入口合并为一行，显示群数量；
- 群级只保存与全局不同的字段，未修改字段继续继承全局；
- 保存是一次事务：写盘失败会回滚内存，不会出现“界面显示已保存、实际没写盘”。

### 全局设置

- 按 `_conf_schema.json` 渲染；
- 修改后点「保存」生效；
- 群覆盖字段的标签、类型、范围、选项由 schema 单源派生。

## 记忆系统

### 两层总结

一次抽取优先产生一条 **episode（事件）**，再产生若干 **atom（原子记忆）**：

- episode 概括整段对话，原子记忆描述具体计划、偏好、事实；
- 原子记忆带 `episode_id`，控制台会折叠到父事件下；
- 每条都有 `brief` 摘要，注入卡片优先使用短摘要。

### 重要性、置信度与有效期

- **重要性 importance**：0–10；
- **置信度 confidence**：0–1，按 major/discussion/daily/chatter/spam 分档；
- **按类型基础有效期**：计划/事件/偏好/关系/事实，范围 **1–365 天**；
- **按类型半衰期**：控制遗忘速度；
- 重要性可随时间衰减，查询时计算，不写回数据库。

### 可见性

一条记忆对当前发言人可见，当且仅当它属于当前会话，或发言人是该记忆的参与者：

- 本群记忆：本群成员可见；
- 全局记忆：只有参与过的人可见；
- 跨群：只有参与过的人在别的会话才能召回；
- 私聊默认不跨群。

### 自动记忆

- **关键词通道**：被 @/引用 Bot 且包含「记住 / 记一下 / 帮我记 / 记着 / 别忘了」时写入；
- **模型通道**：未总结消息达到「累计消息记忆」（默认 50 条）且冷却结束，或会话空闲达到「对话间隔切窗」；
- 指令消息不进入普通历史，也不触发关键词写入；
- 自动记忆不依赖群聊上下文或主动回复开关。

### 召回与注入

- 关键词召回与向量召回并行，RRF 融合后重排；
- 默认总截止 **3 秒**；向量化超时默认 **8 秒**，写入向量化默认 **12 秒**；
- 词法超时会被标记为降级，不写入召回缓存，下一轮可重试；
- 命中结果以临时内容块注入，不修改系统提示词、不写入对话历史；
- 召回缓存默认 45 秒 / 256 条；Embedding 缓存默认 300 秒 / 256 条。

### 召回性能

- SQLite 主表有 `archived / superseded_by / memory_time` 复合索引；
- 语义召回先只取 id + 向量计算相似度，再批量取回 TopK 详情，避免整页大对象；
- 工具检索受单轮时间和并发槽位约束，超时会返回降级提示，不无限占用线程。


## 常见问题

### 自动记忆没有触发

依次检查：记忆 RAG 总开关、自动产生记忆、群级是否关闭、Embedding 提供商、累计条数与抽取间隔、对话间隔切窗是否为 0。

### 记忆时间不对

新记忆使用 AstrBot 全局时区下的真实发送时间；旧版本历史不会批量改写。旧记忆也不会自动补有效期，需要时删除或等待归档。

### `/总结记忆` 提示消息不足

至少需要 3 条记忆历史；重启后运行时历史清空，需要产生新消息再总结。

### 引用或 @ 没有正确发出

确认 React Pattern 与智能回复开启，并确保本轮没有被强制流式输出。

### 回收站怎么看

没有独立回收站页面。删除后底部提示条的「撤销」是恢复入口；数据暂存在 `memory_trash` 表，超期由维护循环清理。
